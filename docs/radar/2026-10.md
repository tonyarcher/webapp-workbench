# Tech radar — 2026-10

This repo exists to test ideas for enterprise code, not to ship product.
This file records the verdicts as of October 2026. Past editions are frozen.
A new quarter writes a new file. Nothing here is edited in place.

## How to read it

Adopt means the repo proves it. Trial means one app proves it this quarter.
Assess means watch it. Hold means the repo already rejected it.

Every Adopt item names the gate that enforces it. A rule without a gate
leaves the radar. The app catalog lives in `apps.json`. The formatter and
lint list lives in `tools/verify.py`. Do not copy either one here.

## Techniques

| Ring   | Item                              | Enforced by                                               |
| ------ | --------------------------------- | --------------------------------------------------------- |
| Adopt  | Database per service              | Each API owns its schema; `DATABASE_URL` names the owner  |
| Adopt  | Version APIs with `X-Api-Version` | Header on each data mapping; probes stay unversioned      |
| Adopt  | JSON log per request              | `service`, `request_id`, `method`, `path`, `status`       |
| Adopt  | Decision log for AI judgments     | JSONL beside sessions; thresholds re-derived from it      |
| Adopt  | Review blocks commit              | `review` agent returns APPROVE or REQUEST-CHANGES first   |

| Trial  | Axe audit per screen              | Baseball proves the pattern; one more app this quarter    |
| Assess | Browser QA for uncovered apps     | Ad hoc against the compose gateway only                   |
| Hold   | Shared package on first use       | Second consumer or headless domain logic, never earlier   |
| Hold   | Node database access for new data | New tables are Kotlin JPA plus Flyway, never Node         |
| Hold   | Server-side HTML DSLs             | UI is web components                                      |

## Trial process

One Trial runs in one app per quarter. Name the app, the gate, and the exit
test before starting. Promote to Adopt or drop it at quarter end. No
standing Trials. The `oxfmt` Trial, if run, lands in a single workspace with
an empty format diff and a passing `verify.py` as its exit test.

## What moves an item

The quarterly review reads the Jev JSONL logs and the CI history, not
opinions. A rule with a bad hit rate drops one ring. A Trial with a passing
exit test rises. Anything without a log entry leaves the radar.
